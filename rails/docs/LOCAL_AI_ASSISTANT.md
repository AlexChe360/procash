# Local ProCash documentation assistant

The assistant widget is available only on the public home page and public documentation. It is absent from both merchant and ProCash admin workspaces. It sends one short question to Rails. Rails selects up to two relevant snippets from `MerchantGuide`, then calls the configured OpenAI-compatible llama.cpp chat endpoint. It has no database tools, account context, secret retrieval or write actions. No conversation history is sent to the model or persisted by the widget. Questions are filtered from Rails request logs.

Development configuration is in the ignored `.env`:

```
AI_ASSISTANT_ENABLED=1
AI_ASSISTANT_BASE_URL=http://sensebox.local:8081/v1
AI_ASSISTANT_MODEL=/home/alex/models/qwen3-1.7b-q4_k_m.gguf
# AI_ASSISTANT_API_KEY=optional-server-token
```

Restart Rails after changing the environment. Set `AI_ASSISTANT_ENABLED=0` to hide and disable the assistant. Do not commit actual API tokens.

The first real development check reached the model and received a Russian answer in approximately 51 seconds. Shorter replies and domain-focused retrieval are used to reduce latency; actual performance depends on the Pi and its load. The widget displays a waiting state, blocks duplicate local submissions and shows documentation links on errors. Rails allows one model request per process, with a 75-second overall timeout, a bounded response size, and a per-process/IP rate limit. Production with multiple workers requires a shared rate limiter/queue if needed; no infrastructure changes have been made.

For a VPS, `sensebox.local` generally will not resolve or route to the home LAN. Configure a reachable private VPN/tunnel address between VPS and Pi, and set `AI_ASSISTANT_BASE_URL` accordingly. Do not expose an unauthenticated model endpoint publicly. Network provisioning and deployment are not part of this local change.

The model's context is 4096 tokens. Requests disable thinking, limit generated tokens and include only relevant public documentation. Treat responses as suggestions; source links are generated by Rails, not by the model. Model output is rendered as text, never HTML. The model may still make mistakes; it does not verify a merchant's actual configuration.

llama.cpp API reference: https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md
