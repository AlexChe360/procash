# Проверка Cross-Site Scripting — 22 октября 2026

## Результат и границы

В проверенных сценариях не подтверждено выполнение пользовательского JavaScript через stored, reflected или DOM XSS. Проверка охватывает Go-приложение и его текущие шаблоны, JavaScript и HTMX. Это результат конкретных проверок, а не гарантия отсутствия любых уязвимостей.

Использовались реальный Chromium, текущий обработчик HTTP и отдельная временная схема PostgreSQL. Рабочие данные не изменялись; настоящие письма не отправлялись. Из этой облачной среды прямое HTTPS-соединение с `procash.kz` блокируется сетевым прокси. Конфигурация внешнего reverse proxy и весь production-периметр не проходили отдельный pentest. Деплой проверяет образ, SQL health и страницу входа на сервере.

## Проверенные источники и вывод данных

| Поверхность | Контексты | Проверки |
| --- | --- | --- |
| Публичная заявка и ошибки валидации | Текст, `input value`, `textarea`, HTMX-ответ 422 | Отражённые и сохранённые имена, контакты, название и комментарий |
| Заявки и пользователи в админке | Заголовки, таблицы, `mailto`, поля и комментарии | Открытие вредоносных данных посетителя администратором |
| Профиль и заведения | Поля формы, заголовок страницы, текст | Запись через форму, повторное чтение, полная страница и HTMX |
| Freedom Pay и iiko | Поля формы, `textarea`, просмотр анкеты и решения | Включая некорректные старые данные, JavaScript URL, номера партнёра и Merchant ID |
| Столы, QR и публичный счёт | Текст, атрибуты, URL, позиции заказа | Данные POS/старой базы, PNG QR, публичный просмотр |
| Заказы, платежи, очередь писем | Таблицы, статусы, темы и ошибки | Вывод потенциально вредоносных сохранённых строк |
| JSON API | JSON-строки, MIME | HTML-символы экранируются; `application/json` и `nosniff` |
| JavaScript и HTMX | DOM, заголовки событий, подмена фрагмента | Отсутствие пользовательских `innerHTML`/`eval` в `app.js`, удаление скриптов из ответов |

`html/template` выполняет контекстное экранирование. Единственное преобразование к `template.HTML` используется при вставке уже скомпилированного и экранированного шаблона в общий layout; пользовательские строки напрямую к этому типу не приводятся. Заголовок в HTMX-фрагменте отдельно проходит `template.HTMLEscapeString`. URL полей интеграций принимаются только с `http`/`https`. Письма отправляются как `text/plain`, а не HTML.

## Усиление защиты

- Добавлена CSP для документов, фрагментов, ресурсов и ошибок: скрипты только с собственного origin, без `unsafe-inline` и `unsafe-eval`; inline-обработчики запрещены. Также запрещены `object`, фреймы и `base`, формы и соединения ограничены собственным origin.
- Стили главной страницы вынесены в `/assets/home.css`. Inline CSS не разрешён; внешние CSS и шрифты допускаются только с используемых Google Fonts origins.
- В HTMX отключены `allowEval`, `allowScriptTags`, автоматическое добавление inline CSS и кеш HTML-истории. Запросы ограничены собственным origin. Старый HTML-кеш очищается; возврат назад загружает актуальную страницу.
- Inline `onchange` у фильтров заменён внешним обработчиком в `app.js`; проверены автоматическая отправка и HTMX-обновления.
- Обнаружена не относящаяся к XSS цепочка DoS в инструментах сборки: `@parcel/watcher` → `micromatch` → `braces` ([GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)). Tailwind CLI закреплял watcher 2.5.1. Через npm override он обновлён до 2.6.0, где эта цепочка отсутствует. Проверены установка и сборка CSS; `npm audit` после изменения сообщает 0 уязвимостей. Эти пакеты не входят в production Go-образ.

## Автоматические регрессии

`internal/app/xss_test.go` и `tests/xss_browser.cjs` проверяют:

- 12 вариантов атак × 24 динамических шаблона × полная страница/HTMX-фрагмент = **576 документов**, открытых в Chromium **без CSP**. Проверяется отсутствие исполняемых тегов, event attributes, внедрённых HTMX-запросов, DOM clobbering и исполнения кода. Таким образом, экранирование проверяется независимо от CSP.
- `script`, `img/onerror`, SVG, выход из `textarea`, `title` и кавычек атрибутов, HTML entities, mutation XSS, JavaScript URLs, `srcdoc`, DOM clobbering и HTMX attributes.
- Реальные переходы и формы посетителя, владельца и администратора; отражённые значения после 422, сохранение профиля, выдачу временного доступа и обязательную смену пароля, фильтры, публичный счёт и JSON API; подтверждение, отмену и выполнение удаления пользователя/заведения с экранированными именами.
- Положительный контроль защиты: намеренно небезопасный синтетический документ с CSP блокирует inline-скрипты и event handlers. В синтетическом HTMX-ответе удаляется даже внешний same-origin скрипт, который сам по себе разрешён `script-src 'self'`.
- Отсутствие CSP-нарушений в штатных сценариях; наличие защитных заголовков в HTML, фрагментах, статических ресурсах и ошибках.

Повторный запуск:

```bash
npm ci
npx playwright-core install --with-deps chromium
TEST_DATABASE_URL='postgres://.../procash_test?sslmode=disable' go test -race -count=1 ./...
npm audit
```

При наличии системного Chromium можно установить `CHROMIUM_PATH=/path/to/chromium`. В облачной среде тест также использует `/usr/bin/chromium`, если он доступен. CI устанавливает браузер Playwright перед Go-тестами. Браузерный тест использует только временную БД с `test` в имени и локальный HTTP-сервер.

## Ограничение проверки Go-зависимостей

Локальный `govulncheck` был запущен, но загрузка `https://vuln.go.dev/index/modules.json.gz` завершилась сетевым `Forbidden`. Этот локальный запуск не объявляется успешным. В GitHub Actions добавлена обязательная отдельная проверка `govulncheck@v1.9.0`, а также `npm audit --audit-level=high`; их сбой останавливает выпуск. Результат проверки Go по базе advisory следует сверять с результатом этого шага в Actions. Просмотр исходного кода, интеграционные тесты и браузерные проверки от этой базы не зависят.
